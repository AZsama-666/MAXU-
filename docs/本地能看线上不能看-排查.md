# 为什么本地能看、线上（www.up9.life）看不了？

## 最可能的原因：Pages 没有用「构建结果」

- **本地**：`npm run dev` 时，Vite 开发服务器会**现场编译**代码，并负责把 `/src/main.jsx` 等路径正确解析成可执行的脚本，所以你能看到完整页面。
- **线上**：浏览器拿到的是一份**已经构建好的** `index.html`。里面的脚本地址必须是**构建产物**里的 JS（例如 `/assets/index-xxx.js`），而不是源码路径（如 `/src/main.jsx`）。

如果线上你看到的是**白屏**或**一直加载不出**，多半是下面两种之一：

---

## 1. GitHub Pages 的「发布来源」选错了（最常见）

若在仓库 **Settings → Pages → Build and deployment** 里：

- **Source** 选的是 **「Deploy from a branch」**，且分支是 **main**、目录是根目录或 `/docs`，

那 GitHub 会直接把 **main 分支的源码**当网站发出去，而不是我们 **Actions 构建好的 dist**。

那样的话，线上用的就是**源码里的 index.html**，里面有：

```html
<script type="module" src="/src/main.jsx"></script>
```

服务器上根本没有 `/src/main.jsx` 这个文件（那是开发时 Vite 才提供的），所以脚本 404，页面空白。

**正确做法：**

1. 打开：**https://github.com/AZsama-666/MAXU-/settings/pages**
2. 在 **Build and deployment** 里：
   - **Source** 选 **「GitHub Actions」**（不要选 Deploy from a branch）。
3. 这样每次推 main 后，会跑 `.github/workflows/deploy-pages.yml`，把 **dist** 发布到 gh-pages，线上用的才是带 `/assets/xxx.js` 的构建结果。

---

## 2. 构建或资源路径有问题

即使 Source 已经选了 **GitHub Actions**，若构建失败或资源 404，也会白屏。

**自检步骤：**

1. 打开 **https://www.up9.life**，按 **F12** 打开开发者工具。
2. 切到 **Console**：看是否有红色报错（尤其是 404、Failed to load）。
3. 切到 **Network**，刷新页面：
   - 看 **index.html** 是否 200；
   - 看下面是否有 **`/assets/index-xxxxx.js`**（或类似名字）的请求：
     - 若是 **404**：说明线上没有正确部署到 dist，或 base 路径不对；
     - 若是 **200**：说明资源能拉到，问题可能在脚本执行或路由。

把 Console 和 Network 里看到的错误/状态码记下来，便于进一步排查。

---

## 小结

| 环境     | 用的 index / 脚本来源           | 结果     |
|----------|----------------------------------|----------|
| 本地 dev | 源码 index + Vite 现场编译       | 能看     |
| 线上正确 | 构建后的 index + `/assets/xxx.js` | 能看     |
| 线上错误 | 源码 index + `/src/main.jsx`（不存在） | 白屏/不能看 |

**优先检查：Settings → Pages → Source 选「GitHub Actions」。** 确认后等一次部署完成，再强制刷新（Ctrl+Shift+R）访问 www.up9.life。
